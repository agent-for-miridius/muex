# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- **`--output <file>`**: Writes the `json` or `html` report to the given file and prints a one-line summary in place of the report. Requires `--format json` or `--format html`. The path is checked before any mutant runs. Without it, `json` still prints to stdout and `html` still writes `muex-report.html`.
- **Test Files**: Each result records the test files `mix test` was given for the mutant (`test_files` in the JSON report, "Test files" in the HTML report and under each survivor in the terminal). For a survivor these are the tests that ran and still passed.
- **Staged Runs with `--staged`**: Tests only lines staged in Git’s index using `git diff --cached`, including the index specified by `GIT_INDEX_FILE` in a pre-commit hook. This lets muex test the staged lines that will be committed. `--staged` cannot be combined with `--since`. `--staged` refuses the run if a file in it has unstaged changes on top of staged changes, and the error names those files. Because muex mutates and tests files on disk but takes its lines from the index, it would test the disk version rather than the version to be committed, and staged line numbers may not match the disk. Files with only unstaged changes are not in the run and do not trigger this refusal.
- **Ignoring Mutants**: `# muex:ignore <reason>` comments skip mutants on their line and the line directly below. A reason is required. Ignored mutants are reported with their reason and left out of the mutation score. Under `--coverage-guided`, ignored mutants are set aside before coverage is classified, so an ignored mutant that no test executes is reported as `ignored`, not `no_coverage`.

### Changed
- **`--since` Uses the Working Tree**: `--since <ref>` now uses `git diff --merge-base <ref>`, including uncommitted edits and matching line numbers to files on disk. On a clean working tree, the result is the same as before. Requires Git 2.30 or later.
- **Elixir 1.16 Required**: muex now requires Elixir 1.16 or later, up from 1.14.
- **`--timeout` Counts from the Suite's Start**: `--timeout` now limits only the time ExUnit spends running the tests. Starting the VM, compiling and starting the app, and anything after the suite ends, are bounded by the larger of 60 seconds and six times `--timeout`. Under load, startup took longer than the tests and timed healthy mutants out. A test helper that sets its own ExUnit formatters hides the suite's start from muex, so the whole run is held to that larger bound.

### Fixed
- **First Mutant per Sandbox Timing Out**: In a plain (non-umbrella) project, each sandbox's first mutant compiled the whole app inside its timeout. muex now compiles every sandbox once, in parallel, before the first mutant, as it already did for umbrellas.
- **`mix test` Outliving the Run**: When the worker pool stopped while mutants were running, it removed the sandboxes and left each `mix test` running, which wrote its build files back into the removed tree. The pool now kills each running `mix test` first.
- **Temp Dir Leftovers**: A muex that was killed left its sandbox pool and `mix test` runner scripts in the temp dir. Each name now holds the muex process's OS pid, and a new run removes those whose process is gone.
- **Elixir Version in Plain Sandboxes**: A plain project's sandbox did not link `.tool-versions`, `mise.toml` and the other mise files, so a version manager's `elixir` shim run there could pick another version than the project pins. The sandbox now links them, as an umbrella sandbox already did.
- **Escript Runs**: The escript built by `mix escript.build` failed every mutation run with `module Mix is not available`, and once given Mix, with `Could not find a Mix.Project`. It now bundles Mix and loads the project's `mix.exs` and config before compiling. Like `mix muex`, it fails a run with no mutants to score when `--fail-at` is above 0.
- **Relative `path:` Dependencies**: A project with a dependency at a relative `path:` outside it, such as `examples/calculator` with `{:muex, path: "../.."}`, failed every mutant: nothing built its dependencies for `MIX_ENV=test`, and from the sandbox the relative path missed the dependency. muex now builds a plain project's dependencies before the run, and stops with Mix's output if they do not build. The sandbox mirrors as many parent directories as the highest relative `path:` climbs.
- **Git Hook Environment for Mix Subprocesses**: muex now unsets Git’s repository-local environment variables for every `mix` subprocess. This prevents project tests that create throwaway Git repositories from acting on the repository being committed to when muex runs from a hook.
- **Coverage Export Cleanup**: Coverage-guided runs now delete each test file’s coverage export after merging it, and also clean it up when the test run fails. muex removes `cover/` if it created the directory and it is empty, while leaving files already in `cover/` alone.
- **`--since` in a Subdirectory**: For a project that is not at the top of its git repository, such as an umbrella inside a monorepo, `--since` matched no files and generated no mutations. The diff now names files from the project root, and relative and absolute `--files` paths both match.
- **`--since` with a textconv Driver**: When a file's diff driver set `textconv`, `--since` took its line numbers from the converted text, so they could miss the source lines. The diff now compares the source.
- **`--since` with `diff.mnemonicPrefix` or `diff.noprefix`**: With `diff.mnemonicPrefix=true`, `--since` matched no changed files and generated no mutations. With `diff.noprefix`, it misread a path starting with `b/`. The diff now always uses the `a/` and `b/` prefixes.
- **Unknown Format**: `--format` is validated with the other options, so an unknown format is refused before the run instead of after it.
- **HTML Write Errors**: A failed write of `muex-report.html` is reported as an error instead of being logged as generated.
- **Invalid UTF-8 in the JSON Report**: A report string holding invalid UTF-8, such as test output or a mutated string literal, made the JSON reporter raise, and the run's report was lost. Each invalid byte sequence is now replaced with U+FFFD (`�`).
- **Invalid UTF-8 in `mix test` Output**: When `mix test` printed invalid UTF-8 and muex stopped the run, the stop message failed with `ArgumentError` (`not valid character data`) and was printed as a list of byte values. The message is now printed as text, with each invalid byte sequence replaced with U+FFFD (`�`).
- **Docs**: README and USAGE said `--format json` writes `muex-report.json`; it prints to stdout. The CI examples now pass `--output muex-report.json`, so the artifact they upload exists.
- **Tests That Never Ran**: When every test chosen for a mutant was excluded, skipped or invalid, `mix test` exited 0 with `Result: 0 tests` (or `N tests, 0 failures, N excluded` before Elixir 1.20) and the mutant was scored survived. It is now `:no_coverage`, with the summary in its `error`, and the terminal says the chosen tests ran none. The umbrella baseline refuses the run when its tests ran none, instead of reporting green.
- **Failures Missed in the Summary**: Before Elixir 1.20 only the first `N tests, M failures` line was read, so in an umbrella a failure in any app after the first was scored survived. A `setup_all` crash, which counts its tests as invalid rather than failed and exits non-zero, was also scored survived. Failures are now summed over every summary, a non-zero exit with no failure counted is a kill, and ANSI colours are removed before the summary is read.
- **Uncompiled Mutants Scored Killed**: Mix treats a file as unchanged when its size and its mtime (whole seconds) match the last compile, so a mutant the same size as the one before it, written within the same second, was never compiled. Its module was missing, every test failed, and the mutant was scored killed without being tested. Each mutant is now padded with trailing newlines to a size no compile has seen; no code or line number changes.
- **Worker Crashes**: An exception or exit inside muex while running a mutant was recorded as `:timeout`, which the high bound of the score counts as killed. It is now `:invalid`, with the error in the report.
- **Equivalent Mutants**: Mutants `Muex.Equivalence` judges equivalent were dropped before the run and appeared in no report, although the README says they are reported. They are now results with status `:equivalent`, shown in every report and still left out of the score. The JSON summary now counts `equivalent` and `no_coverage`, and its `total` now includes equivalent mutants. The HTML report has cards and filters for both. A run that has only equivalent mutants left reports them and exits as a run with no mutants did before.
- **Broken Runs Scored as Invalid Mutants**: `mix test` compiles the whole project, so a mutant was scored `:invalid` for a compile error in any file, including one it never touched: a dependency edited during the run, a sibling app, a test file. Every later mutant then came back invalid too, and the score, which leaves invalid mutants out, looked healthy. When a mutant's run does not compile or stops before ExUnit reports, the chosen tests are run again with no mutation applied: with every test excluded when the compile failed, which compiles and loads everything and runs nothing, and with the tests otherwise. Which file the error names does not decide it, because a mutant can break a file that depends on it (a caller of a macro it changed) and a change elsewhere can break the mutated file. If the unmutated run fails the same way, the run stops with the files the error names and nothing scored, as the umbrella baseline does. If it passes, the mutant is still `:invalid`. Each invalid mutant costs this one extra run.
- **`a * 1` and `a / 1` Called Equivalent**: `Muex.Equivalence` treated `a * 1` to `a / 1` as an identity swap and dropped the mutant before the run. `/` always returns a float, so `2 * 1 === 2 / 1` is false and a test can kill it. The mutant is now run. The `a + 0` vs `a - 0` and shift-by-zero rules are unchanged.
- **Integer and Float Literals Called Equivalent by TCE**: Compiled code was compared with `==`, so `4` and `4.0`, or `-0.0` and `0.0`, matched. A mutant such as `{:ok, 4 * 1}` to `{:ok, 4 / 1}` was reported equivalent and never run, though `=== {:ok, 4}` kills it. The comparison is now exact.
- **Function Captures Mutated as Division**: In `&Path.dirname/1` the `/` names the arity, but Arithmetic mutated it as division and FunctionCall as a call, giving captures that do not compile (`&(Path.dirname() * 1)`, `&1`). For arity 1, `/ to *` was also called equivalent. The `/` of `&Mod.fun/arity` and `&fun/arity` is no longer offered to any mutator; the function and a remote capture's arity still are. Division inside a capture, `&(&1 / 2)`, is mutated as before.
- **Maps, Structs and `::` Mutated as Calls**: FunctionCall mutated map and struct literals and `::` (in string interpolation and bitstring segments) as calls. Swapping arguments gave code that does not compile (`%(%{host: "h"}, URI)`, `binary :: Kernel.to_string(x)`) or reordered map keys, which changes nothing unless two keys are equal at runtime. They are no longer mutated; calls inside them still are.
- **Equal Code Twice on One Line**: A mutation replaced every node on its line that was equal to the one it came from, so in `x + 1 + (x + 1)` mutating one `x + 1` rewrote both: the code run was not the mutant reported, and the mutants for the two copies were the same. `Muex.Mutator.walk/3` now records each node's position in the AST as `:ast_path`, and `Muex.Compiler` replaces only the node there. A mutation with no position, or one that does not lead to an equal node, is matched by line as before. The report format is unchanged.
- **Definition Heads and Patterns Mutated as Calls**: FunctionCall removed a definition's head, turning `def add(a, b)` into `def nil`, and removed or swapped `|`, `<>` and `<<>>` in patterns (parameters, and the left of `=`, `<-` and `->`), unbinding variables or giving patterns that do not compile. It also removed a bitstring generator's `<<>>` and the call a pipe feeds, leaving `for nil` and `x |> nil`. A definition's head and a generator's `<<>>` are no longer offered to any mutator, FunctionCall leaves patterns alone, and it no longer removes a pipe's target; Pipe still drops the stage. Guards, `cond` conditions and `receive` timeouts are still mutated. Runs have fewer mutants, since heads are no longer mutated.
- **Module Attribute Names Mutated as Calls**: FunctionCall read `@timeout 5_000` as a call `timeout(5_000)` and removed it, leaving `@nil`, which does not compile. An attribute's name is no longer offered to any mutator; the attribute and its value still are.
- **Sigils That Never Compile**: FunctionCall swapped a sigil's text and modifiers and removed its text, and Literal mutated its modifiers (`~r/ab+c/i`); none of these compile. A sigil's modifiers are no longer offered, and its text is neither removed nor swapped. The sigil can still be removed and its text mutated.
- **`in` in Guards That Never Compile**: In a guard the right of `in` must be a list or range at compile time, so FunctionCall's swap (`[1, 2] in x`) and its removal of the right side (`x in nil`) did not compile. Neither is offered in a guard now. Outside guards `in` is still swapped, and inside one a range's bounds are still swapped and mutated.
- **`raise` Arguments Swapped**: FunctionCall swapped `raise(ArgumentError, "neg")` to `raise("neg", ArgumentError)`, which does not compile when the second argument is a literal string, number or list, and otherwise only raises something else. `raise` and `reraise` arguments are no longer swapped; the call can still be removed.
- **Statement Deletions That Never Compile**: StatementDeletion deleted the only definition of a function, macro or guard the module still calls, pipes into or captures, a `defstruct` while the module uses a struct, and `x = ...` while a later statement reads `x`. Those deletions are skipped, so runs have fewer mutants. Deleting one clause of several, an unused definition, or a rebinding of an already bound name is still a mutant.
- **`with` Clause Deletions That Never Compile**: WithClause deleted a `<-` clause whose bindings a later clause or the `do` body reads. Those deletions are skipped unless an earlier clause already binds the name, so runs have fewer mutants.
- **Capture Arities That Never Compile**: Changing the arity of a local, imported or operator capture (`&+/2` to `&+/3`) gave code that does not compile. Only a remote capture's arity (`&Mod.fun/2`) is still mutated, so runs have fewer mutants, including local arity changes that would compile.
- **Capture Placeholders Lost**: Mutators changed a placeholder's number (`&1` to `&0`) and, inside `&(...)`, replaced code with code missing one of its placeholders (`&(&1 + &2)` to `&(nil + &2)`, `&(&1 / 2)` to `&1`), giving captures that do not compile. Neither is offered now, so runs have fewer mutants; renumberings that would compile, such as `&(&1 + &2)` to `&(&1 + &1)`, are lost too.
- **Remote Function Names Mutated**: Literal mutated the function name of a remote call or capture as an atom, turning `Enum.join(list, ",")` into `Enum.mutated_atom(list, ",")`. In a module body that does not compile; in a function it compiles with a warning and raises when called. The function name is no longer offered to any mutator; the module, the arguments and the field of a map field access (`m.key`) still are.
- **Module-Body Calls That Never Compile**: Code in a module body outside its definitions runs when the module compiles, but FunctionCall removed calls whose value it uses (`defstruct nil`, `for f <- nil`) and swapped arguments (`Enum.join(",", list)`, `Module.register_attribute(:acc, __MODULE__, ...)`). There FunctionCall now swaps nothing and removes only the body's own statements. Calls inside definitions are mutated as before.
- **Attribute Definitions Read at Compile Time Removed**: FunctionCall removed an attribute definition such as `@limits [1, 2]` while a guard, a pattern or the module body read it, which does not compile. Those removals are skipped; an attribute read only in function bodies is still removed.
- **Attribute Registrations Read at Compile Time Deleted**: StatementDeletion and FunctionCall removed `Module.register_attribute(__MODULE__, :acc, accumulate: true)` while the module body read `@acc` (`defstruct [:z] ++ @acc`), which then holds one value instead of a list and does not compile. Those removals are skipped; a registration read only in function bodies is still deleted.
- **Duplicate Module-Body Removals**: In a module body FunctionCall replaced a call statement with `nil` while StatementDeletion deleted the same statement, so each was tested twice. FunctionCall now removes only attribute definitions and the body's last statement there, which StatementDeletion does not delete.
- **Directives Deleted**: StatementDeletion deleted `use`, `import`, `alias` and `require` statements. Code after them that uses a macro or function they bring in (`band(3, 1)` after `import Bitwise`, `schema` after `use Ecto.Schema`) then does not compile, in a module body or a function. Directives are no longer deleted, so runs have fewer mutants, including `alias` deletions that compile and only raise.
- **Module-Body Call Arguments That Make Compilation Raise**: Literal and Boolean changed literal arguments of calls in a module body, which runs when the module compiles: `@m Map.fetch!(m, :a)` to `:mutated_atom`, and `Module.register_attribute(__MODULE__, :acc, accumulate: true)` to `:mutated_atom` or `accumulate: false`, raise there. In a module body a named call's literal arguments and literal keyword option values are no longer mutated, so runs have fewer mutants, including some that compile (`div(10, 3)` to `div(10, 4)`). Operator operands, `defstruct` and `defexception` defaults, and the same calls in functions are still mutated.
- **Erlang Modules Renamed in Module Bodies**: Literal renamed the Erlang module of a remote call in a module body (`@bin :erlang.atom_to_binary(:ok)` to `:mutated_atom.atom_to_binary(:ok)`), which does not compile. It is no longer offered there; in a function, where the renamed call compiles and raises when called, it still is.
- **`<>` Operands Removed**: FunctionCall replaced an operand of `<>` with `nil` (`nil <> "y"`), which Kernel rejects when the code compiles. Operands of `<>` are no longer removed; the `<>` itself still is.
- **Coverage Export Notices**: With `--coverage-guided`, `:cover`'s merged coverage file paths and import notices are printed only with `--verbose`.
- **Clause Deletion Locations**: Case, cond, and with clause-deletion mutants are now reported on the deleted clause's own line (`->`, or `<-` for `with`), so `--since` and `--staged` can scope deletions to changed clauses rather than the enclosing `case`, `cond`, or `with` line.
- **Function-Based Complexity Filtering**: `--min-complexity` (`min_complexity`, default `2`) now uses the containing function's cyclomatic complexity (`:function_complexity`) instead of the replacement node, so literals and removed calls are no longer always scored as `1`; mutations outside functions use their own node, and decision points in `do:` keyword bodies are counted.
- **Tests Naming a Module Only as a Value**: Dependency analysis tied a test file to a module only through `alias`, `import` or a remote call, so a test passing the module as a value, as in `live_isolated(conn, MyAppWeb.PageLive)`, was not selected for it. When another test named the module, only that test ran and the mutant could survive; with `--coverage-guided`, this hit lines without coverage data, such as a `def` header. Every module name a test file writes now counts, including in arguments, structs and tuples, and a name starting with an alias is also counted under the module it expands to.

## [0.10.0] - 2026-09-12

### Fixed
- **Umbrella Project Root**: `--app <app>` now resolves the umbrella root as the project root instead of `apps/<app>`, whose `config_path: "../../config/config.exs"` pointed outside the sandbox.
- **Umbrella Sandboxes**: Umbrella sandboxes now clone `apps/` and `_build/<env>` (copy-on-write where supported) instead of linking each app, so `in_umbrella` dependencies resolve inside the sandbox and no recompile writes into the real build. Every mutant used to come back `:invalid`. Each sandbox is compiled once before the first mutant, outside the per-mutant timeout. The sandbox's parent mirrors the project's parent, so tests that read files beside the project still find them.
- **Test Selection**: `Muex.DependencyAnalyzer` joined module name parts without a separator (`:ElixirMyAppFoo`), so no test file was ever selected and every mutant ran the whole test directory.
- **Baseline Check**: In umbrellas, the selected tests are run once with no mutation applied, and the run stops if any fail, instead of reporting every mutant they judge as killed.
- **Empty Test Selection**: A mutant with no selected test file stops the run. `mix test` given no files runs every test.
- **Writes Through Links**: Files outside `apps/<app>/` are refused in umbrellas, and a mutant is never written or restored through a symlink into the real project.
- **Sandbox Cleanup**: Sandboxes are removed when setup, warm-up or the baseline fails.
- **Worker Pool Crash**: The pool no longer crashes on the `{:EXIT, port, :normal}` messages that `System.cmd` sends during sandbox setup.

### Changed
- **Kill Evidence**: A killed mutant's `error` field now holds the first ExUnit failure block (test name, file:line, assertion), shown in JSON and HTML reports.
- **Pool Size**: No more sandboxes are created than there are distinct mutated files.
- **Progress Output**: Warm-up and baseline progress lines go to stderr, so `--format json` output stays parseable.

## [0.9.0] - 2026-08-26

Special thanks to [@e-fu](https://github.com/e-fu) for extensive bug reports, detailed reproductions, and code contributions!

### Fixed
- **Behavior Definition vs Implementation Filtering**: `Muex.FileAnalyzer` no longer skips modules that implement a behavior (`@behaviour SomeBehaviour`). Only modules defining multiple `@callback` annotations are skipped as behavior definitions ([#22](https://github.com/Oeditus/muex/issues/22)). (Credit: [@e-fu](https://github.com/e-fu))
- **Threshold Enforcement on Empty Runs**: `mix muex` now enforces the `--fail-at` threshold when zero mutations are tested rather than silently passing ([#22](https://github.com/Oeditus/muex/issues/22)). (Credit: [@e-fu](https://github.com/e-fu))
- **Sandbox File Linking**: Symlinked all files and subdirectories in the test root (`test/`) into worker sandboxes when narrowing `--test-paths`, ensuring test modules can access compile-time and runtime fixtures, golden files, and schemas ([#25](https://github.com/Oeditus/muex/issues/25)). (Credit: [@e-fu](https://github.com/e-fu))
- **Invalid Verdict Error Details**: Preserved error details in `classify_test_result` when test runs yield `:invalid` verdicts, preventing `error: null` in output reports ([#25](https://github.com/Oeditus/muex/issues/25)). (Credit: [@e-fu](https://github.com/e-fu))
- **Dotted Exception Name Matching**: Updated `compile_error?` regex pattern to support namespaced Elixir exceptions such as `File.Error` and `Jason.DecodeError` ([#25](https://github.com/Oeditus/muex/issues/25)). (Credit: [@e-fu](https://github.com/e-fu))
- **Accurate Node Replacement Matching**: Matched mutations by their original node AST line (`:original_line`) rather than reported display line ([#27](https://github.com/Oeditus/muex/pull/27)). (Credit: [@e-fu](https://github.com/e-fu))
- **App Detection in Sandbox**: Improved OTP application name detection from project definitions rather than guessing from `_build` markers ([#26](https://github.com/Oeditus/muex/pull/26)). (Credit: [@e-fu](https://github.com/e-fu))
- **Unmeasured Runs Verdict Handling**: Fixed unmeasured test runs from being incorrectly counted as killed mutants ([#20](https://github.com/Oeditus/muex/issues/20) / [#21](https://github.com/Oeditus/muex/pull/21)). (Credit: [@e-fu](https://github.com/e-fu))

### Changed
- **Mutator Type Spec**: Made `:original_ast`, `:original_line`, and `:equivalent` optional keys in `@type Muex.Mutator.mutation()` map spec to prevent type friction for external mutators.
